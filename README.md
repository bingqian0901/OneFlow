# 万象 OneFlow

**一个入口，连接生活的每一步。**

面向产品经理面试演示的高保真 C 端交互 Demo。用自然语言与可操作卡片组织生活服务，在同一份本地状态中同步手机入口、任务执行、服务连接和多设备模拟视图。

## 在线部署

本项目使用 GitHub Pages，站点地址为 https://bingqian0901.github.io/OneFlow/ 。

推送到 `main` 后，`.github/workflows/deploy.yml` 自动安装依赖、运行状态测试、构建并部署 `dist`。也可以在 GitHub Actions 页面手动运行。仓库 Settings → Pages 的 Source 应设为 GitHub Actions。

Vite 使用相对资源路径，兼容 `/OneFlow/` 子目录。在线与本地的数据分别保存在各自浏览器站点的 LocalStorage 中，不会将个人演示记录同步到 GitHub。

## 运行

需要 Node.js 20.19+ 或 22.12+（本次使用 Node.js 24）。

```powershell
npm install
npm run dev -- --port 5173
```

浏览器打开 http://localhost:5173 。开发服务器监听局域网地址，同一网络的手机可使用终端显示的 Network 地址访问；推荐直接使用浏览器移动设备模式。

```powershell
npm run build   # TypeScript 检查与生产构建
npm run preview # 预览生产构建
npm run check   # 确认门槛、设备同步、离线与授权的状态测试
```

## 功能与页面

- **首页**：自然语言入口、模拟语音、四个生活场景、当前任务、设备控制和快捷服务。
- **AI 对话**：保留任务上下文的文字输入、分步规划、可编辑推荐卡片、完整执行确认、时间线与结果入口。
- **任务**：进行中／待确认／已完成，点击查看执行详情；暂停、恢复、取消未执行步骤、失败重试及跳过。
- **服务**：六类服务 Agent、能力说明、模拟应用连接与授权。缺少授权时先连接，再确认执行。
- **我的**：个人昵称与偏好、10 台模拟设备、在线／离线切换、温度／灯光／模式控制、演示数据重置。
- **桌面协同视图**：电视、汽车、电脑和智能家居实时联动；移动端使用同一组件的弹窗预览。

## 推荐演示路径

### 1. 电影之夜（约 2 分钟）

首页点击「科幻电影之夜」→ 开始规划 → 选择《星际穿越》→ 添加宇航员模型与星空氛围灯各一件 → 加入本次购物清单 → 选择客厅电视，保持「先打开影片详情页」→ 调整温度和灯光 → 确认开启观影模式 → 检查完整方案 → 确认执行。

观察右侧电视出现影片，切到家居查看空调与灯光。完成后查看购物清单，合计 ¥218；点击「模拟确认下单」后仍需要在独立订单弹窗再次确认。电视「开始播放」会更新播放状态。

可用语句：`就看第二部`、`先不要买周边`、`空调改成25度`。选片语句在规划阶段生效。

### 2. 下班归家（约 3 分钟）

首页点击「下班归家」→ 开始规划 → 拖动温度，或输入 `空调改成25度` → 输入 `不要辣的，换成有汤的`，观察其他设置保留 → 查看归家计划 → 确认归家计划。

从模拟 18:10 开始，点击「推进模拟时间」依次前往设备启动节点。无需真实等待。计划执行期间输入 `我堵车了，预计晚20分钟到家`，确认后只调整尚未执行的安排。已经开启的设备不会关闭或回退。已执行空调改温会新增一项需确认的控制动作。

### 3. 异常与可控性（约 1 分钟）

归家执行到 18:15 前，点击热水器面板，关闭「设备在线状态」。推进时间后显示连接失败；继续推进，空调、灯光仍执行。恢复热水器在线再重试，或跳过该步骤。取消任务仅取消剩余步骤，保留已完成记录与设备状态。

### 4. 旅行与办公（各约 1 分钟）

- 旅行：修改城市、日期、预算、交通、酒店和路线 → 确认行程并添加至日历 → 确认执行 → 车机显示目的地；日历记录保存在任务结果中。
- 办公：查看《产品方案 V1.0》及三项待办 → 设置提醒时间 → 确认执行 → 电脑收到文档与上下文 → 打开文档；可继续输入 `提醒改成21:00`。

## 数据与安全边界

`Task`、`TaskStep`、`Device` 和服务连接共用 React 状态，并通过 LocalStorage 的 `oneflow-demo-v1` 保存。刷新后恢复任务、执行记录、设备和偏好；未完成的运行中步骤继续模拟执行。

- 未确认的任务不控制设备。
- 执行器检查运行状态、模拟时间、设备在线和服务授权；已完成步骤不会重复执行。
- 各设备步骤独立失败，不将离线伪装为成功。
- 商品与晚餐只创建清单／待确认订单，需要独立确认才能生成演示订单。
- 所有内容、价格、导航、日程与订单均为本地演示，不调用大模型、支付、硬件协议、真实视频播放或第三方服务。
- 影片是演示信息，不声称模拟平台拥有播放版权。提醒不会创建操作系统通知。
- 场景视觉、电影视觉和房间插画由本地 CSS 与系统 Emoji 构成，无外部图片加载依赖。

## 文件结构

```text
src/
  main.tsx                    React 入口
  App.tsx                     五个页面、对话场景、控制与确认弹窗
  components/DevicePreview.tsx 多端共享的设备模拟视图
  components/TaskSummary.tsx   场景确认摘要和旅行预算计算
  components/SceneArt.tsx      本地场景插画
  model.ts                    类型、Mock 数据、计划生成与任务执行器
  style.css                   响应式布局、CSS 插画、卡片与动效
public/favicon.svg            本地品牌图标
scripts/check.ts               状态逻辑回归检查
scripts/browser-check.js       Playwright CLI 电影流程
scripts/browser-home-check.js  Playwright CLI 归家流程
scripts/browser-extra-check.js 移动端、授权、旅行及办公回归
scripts/browser-guard-check.js 跳过、取消、语音与重置回归
output/playwright/             浏览器验证截图
VALIDATION.md                  本次验证结果
```

浏览器回归使用 `@playwright/cli` 的独立会话执行；脚本通过真实点击、输入与键盘操作推进页面，读取 LocalStorage 断言最终状态，不伪造执行结果。

## 演示准备

推荐 1440px 左右的桌面视口，同时观察操作区与设备响应。390px 手机视口显示底部五栏导航。重复演示可在「我的 → 重置演示数据」恢复初始状态。
